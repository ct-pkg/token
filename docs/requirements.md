## 1 一句话需求

给一段 UTF-8 字节序列，用整数运算在 O(n) 时间、零堆分配下给出一个**偏保守**的 token 数；
误差带可判定，分段累加与整体估算逐值一致，结果跨平台、跨 locale、跨运行确定。

## 2 「粗估」的边界

### 2.1 估算对象

- 输入是 UTF-8 字节序列，长度由调用方显式给出；可含 ASCII、CJK、其他 Unicode、内嵌 `\0`
  与畸形字节。
- 输入视为**已经是最终要发送的文本**；消息头、role、chat 模板、工具调用 JSON 的包装由调用方
  自行拼接并计入，本包不建模（Q-04）。
- 不估算：special token、图片 / 音频 / 视频 / PDF 等多模态输入、模型侧的隐藏开销。

### 2.2 单位与参考

- 1 token = **参考 tokenizer** 的一个 token，整数。参考 tokenizer 是校准实验选定的一个具体实现
  （名称 + 版本 + 精确命令），不是「某个模型大致」（Q-03）。
- 估算是**偏保守**的：预算场景下欠估比高估危险。因此误差带对欠估更严（§2.3）。
- 估算值不消费、不修改输入；同一字节序列在同一版本内结果恒定。

### 2.3 误差带（可判定）

对语料中的样本 `s`，记 `ref(s)` 为参考 tokenizer 的 token 数，`est(s)` 为本包输出：

- 相对偏差 `e(s) = (est(s) - ref(s)) / ref(s)`
- 欠估 `u(s) = max(0, -e(s))`
- 聚合比 `R = Σest / Σref`
- `p95` = `|e|` 的 95 分位

| 语料 | 每样本欠估上限 `u` | 聚合比 `R` | `p95(|e|)` |
| --- | --- | --- | --- |
| 英文自然语言 | ≤ 10% | 1.00 – 1.25 | ≤ 25% |
| 中文自然语言 | ≤ 10% | 1.00 – 1.35 | ≤ 30% |
| CT / C 源码 | ≤ 10% | 1.00 – 1.30 | ≤ 30% |
| 混合（文本 + 代码） | ≤ 10% | 1.00 – 1.30 | ≤ 30% |

- 每类语料 ≥ 20 条，每条 1–64 KiB；另加 1 条 ≥ 1 MiB 的长样本，只计聚合与耗时，不进 `p95`。
- 任何一类不达标：改权重表或按模型族拆档案（Q-01），**不得放宽带**。
- 权重表是暂定值（§R-04）；校准后只允许改权重数字并同步夹具，不允许改指标定义与带宽。
- 不承诺逐样本的对称误差上界；只承诺表里的欠估上限、聚合比与 `p95`，不承诺逐 token 对齐。

### 2.4 为什么不做精确

- BPE / SentencePiece / WordPiece 需要词表与合并规则，随模型版本变化；内置会把包变成模型数据仓库。
- 预算管理只需要「不会明显低估」，不需要逐 token 对齐；精确对齐属于 tokenizer 包，不属于本包。

### R-02 输入契约

- **问题**：估算必须按调用方给出的长度工作，不能被 NUL 截断，也不能读到边界外。
- **输入 / 期望**：`const char *p` + `int len`；`len` 是唯一长度契约，内嵌 `\0` 按普通字节计数；
  `len < 0` 或 `p == NULL && len > 0` 返回 `-1`；`p == NULL && len == 0` 返回 `0`；
  不修改输入，不读取 `p[len]` 或更远的字节。
- **验收**：
  - 夹具用 `malloc(len)` 分配**恰好 len 字节、无结尾 NUL** 的缓冲区，填充后调用；
    ASAN 退出 0，无 `heap-buffer-overflow`。
  - `"abcd\0"` 以 `len=5` 传入，结果为 2（`"abcd"` 的 4 units + 内嵌 NUL 的 2 units，共 6 units）；
    结果等于按 units 累加 `"abcd"` / `"\0"` 两段后再一次取整，且与 `len=4` 的 `"abcd"`（1）不同。
  - `p=NULL, len=0` 返回 0；`p=NULL, len=1` 返回 -1；`len=-1` 返回 -1。
- **负例**：用 `strlen(p)` 取长度的实现在 `"abcd\0"` 上只算前 4 字节并返回 1，断言必须变红；
  读 `p[len]` 的实现在 ASAN 下必须报越界。
- **非目标**：不接收 NUL 结尾字符串的隐式长度；不复制输入；不做编码转换。
- **依赖 / 阻塞**：`char *` + 显式长度 + 下标已支持（`ct-lang/lib/std/Str.h.ct:33-48`；
  `ct-lang/test/ast/230_str_embedded_nul/prog.ct:7-10`）。

### R-03 分类表

- **问题**：必须先把字节/码点分到确定的类，估算才可复现；类边界不能靠感觉。
- **期望**：按下列顺序分类，权重以「1/4 token」为单位（`units`）：

| 类 | 判定 | 权重（units） |
| --- | --- | --- |
| ASCII 字母/数字/空白 | `0x30-0x39`、`0x41-0x5A`、`0x61-0x7A`、`0x20`、`0x09`、`0x0A`、`0x0D` | 1 |
| ASCII 其他 | 其余 `0x00-0x7F`（含 `\0`、控制符、标点、`0x7F`） | 2 |
| CJK 及关联 | `U+3000-303F`、`U+3040-30FF`、`U+3400-4DBF`、`U+4E00-9FFF`、`U+AC00-D7AF`、`U+F900-FAFF`、`U+FF00-FFEF`、`U+20000-3FFFF` | 4 |
| 其他 BMP | 其余 `U+0080-FFFF` | 3 |
| Astral 非 CJK | `U+10000-1FFFF`、`U+40000-10FFFF` | 8 |
| 畸形字节 | 不能构成合法 UTF-8 序列的每个字节 | 4 |

- 判定顺序：先判 ASCII；否则解码 UTF-8；合法码点先查 CJK 区间（含 astral CJK），再查 astral
  非 CJK，最后落其他 BMP；解码失败的**每个**字节单独记畸形，不做替换字符修补。
- **验收**：
  - 表驱动夹具覆盖每个类的下界、上界与跨界点：`U+007F/0080`、`U+07FF/0800`、`U+2FFF/3000`、
    `U+1FFFF/20000`、`U+3FFFF/40000`、`U+FFFF/10000`。
  - 同一码点重复 4 次时，CJK 类给 4 token，其他 BMP 类给 3 token（区分两类，不靠单字符的四舍五入）。
  - 畸形序列 `0xFF`、`0xC0 0x80`、`0xED 0xA0 0x80`、截断的 `0xE4 0xB8` 各一条夹具，逐字节计数。
- **负例**：把所有 `≥ 0x80` 的字节都记畸形（4 units/字节）会把 `"世"` 算成 3 token 而不是 1；
  把其他 BMP 记成 4 units 会让 4 个 `U+00E9` 算成 4 而不是 3。
- **非目标**：不做字形簇/ZWJ 合并（Q-09）、不做语言识别、不按词表分类。
- **依赖 / 阻塞**：位运算与 `unsigned char` 已支持（`ct-lang/test/ast/19_bitops/prog.ct:17-18`；
  `ct-lang/docs/language-spec.md:1024`）。

### R-04 参考公式与取整

- **问题**：分段与整体要逐值一致，就不能在每个片段上各自四舍五入；取整只能发生一次。
- **期望**：`units = 1*a + 2*b + 3*c + 4*d + 8*e + 4*f`，其中 `a`=ASCII 字母/数字/空白字节数，
  `b`=ASCII 其他字节数，`c`=其他 BMP 码点数，`d`=CJK 码点数，`e`=astral 非 CJK 码点数，
  `f`=畸形字节数；`tokens = (units + 3) / 4`（整数向上取整）。全程整数，无 `float`/`double`，
  累加器用 64 位 `long`。
- **验收**（精确夹具，全部逐值相等）：
  - `""`→0；`"a"`→1；`"ab"`→1；`"abc"`→1；`"abcd"`→1；`"abcde"`→2。
  - `"hello, world."`→4；`"int x=1;"`→3；`"a b"`→1；`"a  b"`→1；`"12345"`→2。
  - `"世界"`→2；`"你好，世界"`→5；`"日本語"`→3；`"한글"`→2；`"a世"`→2。
  - `"\0"`（len=1）→1；`"!!!!"`→2；`"é"`→1；`"éééé"`→3；`"世界世界"`→4。
  - `"€"`→1；`"😀"`→2；`"𐀀"`（U+10000）→2；`"𠀀"`（U+20000）→1。
  - `0xFF`→1；`0xC0 0x80`→2；`0xED 0xA0 0x80`→3；截断的 `0xE4 0xB8`→2。
- **负例**：把 `(units+3)/4` 改成 `units/4`，`"a"` 会变成 0，第一条断言变红；对每个片段先
  `ceil` 再求和，会在 R-11 的分段夹具上变红。
- **非目标**：不引入浮点系数、不按字符数乘模型系数、不做运行时学习。
- **依赖 / 阻塞**：整数除法与 `long` 已支持（`ct-lang/test/ast/228_pub_generic_fn/prog.ct:15`）。

### R-05 空串与最短输入

- **问题**：空输入必须为 0，非空输入不能为 0；边界不能靠调用方兜底。
- **期望**：`len=0` → 0；任何 `len>0` 的输入 → `≥1`；单个 ASCII 字母、单个 CJK 码点、单个
  畸形字节都 → 1。
- **验收**：`""`、`" "`、`"\n"`、`"a"`、`"世"`、`0xFF` 六条夹具；`est("")==0` 且
  `est(任意 len>0)>=1` 对随机 10,000 条短字节串成立。
- **负例**：无符号减法或空指针早退把非空输入算成 0，断言变红。
- **非目标**：不为空输入分配对象、不返回特殊哨兵（只返回 0）。
- **依赖 / 阻塞**：无。

### R-06 纯文本与 ASCII

- **问题**：英文自然语言与代码必须落在 §2.3 的误差带内，而不是「大致像」。
- **期望**：英文自然语言语料满足欠估 ≤10%、聚合比 1.00–1.25、`p95 ≤25%`；ASCII 标点与空白
  按 R-03 的权重，换行不特殊处理。
- **验收**：
  - `test/run.sh token/corpus en` 输出每条 `ref/est/e`，聚合比与 `p95` 由脚本计算并与 §2.3 比对。
  - 精确夹具覆盖 `"hello, world."`、`"a b"`、`"a  b"`、`"!!!!"`、`"12345"`。
- **负例**：把 ASCII 标点也记 1 unit，`"!!!!"` 会从 2 变成 1；把空白记 2 units，`"a  b"` 会从
  1 变成 2；两条都会变红。
- **非目标**：不做词法/句法分析、不做词形还原、不按语言切换规则。
- **依赖 / 阻塞**：语料与参考计数待 R-15 固化；当前为**软阻塞**（未校准）。

### R-07 含 CJK 的估算

- **问题**：CJK 的 UTF-8 多字节不能按字节摊成 ASCII，也不能把 3 个字节算成 3 个 token。
- **期望**：中日韩统一表意文字、扩展 A/B–H（本文件用 `U+20000-3FFFF` 宽区间）、假名、谚文、
  全角标点、CJK 兼容表意文字按 R-03 的 CJK 类计数；中文自然语言语料满足 §2.3 的带。
- **验收**：
  - 精确夹具：`"世界"`→2、`"你好，世界"`→5、`"日本語"`→3、`"한글"`→2、`"𠀀"`→1。
  - `test/run.sh token/corpus zh` 输出聚合比、`p95` 与欠估最大值，按 §2.3 判定。
  - 混排夹具 `"a世b"` 的分段累加与整体估算逐值一致（R-11）。
- **负例**：把 `"世"` 的 3 个字节都记 ASCII 其他（2 units/字节）会得到 2 token 而不是 1；把每个
  续字节当独立码点（各记 1 token）会把 `"世界"` 算成 6 而不是 2。
- **非目标**：不做中文分词、不区分简繁、不做注音/假名转换。
- **依赖 / 阻塞**：UTF-8 解码用 C 级位运算；已支持（`test/ast/19_bitops/prog.ct:17-18`）。

### R-08 其他 Unicode 与畸形序列

- **问题**：重音拉丁、西里尔、希腊、emoji、astral 与畸形输入不能崩溃、不能读越界，结果必须确定。
- **期望**：其他 BMP 码点 3 units；astral 非 CJK 8 units；畸形字节每字节 4 units；overlong、
  surrogate、超范围、截断序列都按「每个非法字节」计数；不插入 U+FFFD，不做编码修复。
- **验收**：精确夹具 `"é"`→1、`"éééé"`→3、`"€"`→1、`"😀"`→2、`"𐀀"`→2、`0xFF`→1、
  `0xC0 0x80`→2、`0xED 0xA0 0x80`→3、`0xE4 0xB8`→2；ASAN 下无越界。
- **负例**：把截断的 2 字节序列替换成一个 U+FFFD 会得到 1 token 而不是 2；把 astral 非 CJK
  记成 4 units（与其他 BMP 混同）会把 `"😀"` 算成 1 而不是 2；两条都变红。
- **非目标**：不验证 UTF-8 合法性、不做安全过滤、不修复数据。
- **依赖 / 阻塞**：无。

### R-09 无状态函数接口

- **问题**：大多数调用点是「一段字符串算一次」，接口必须无状态、零分配、可重入。
- **期望**：提供
  `long token_estimate(const char *p, int len)` 与
  `long token_estimate_str(Str s)`；后者等价于前者传入 `s.data, s.len`；返回 `long`，
  不分配堆内存、不修改输入、不持有静态可变状态。
- **验收**：
  - `sizeof(long) >= 8`（支持平台 LP64）；`token_estimate_str(str_from("世界")) == token_estimate("世界", 6)`。
  - 分配拦截器在调用前后计数相等（0 次 `malloc/calloc/realloc/strdup`）。
  - 同一输入连续调用 10,000 次结果恒定；两个线程并发调用同一输入结果一致（R-17）。
- **负例**：`token_estimate_str` 用 `strlen` 取长度在内嵌 `\0` 的 `Str` 上结果错误；把返回类型
  收窄成 `int` 后，调用方汇总多条消息时在超过 2^31 的预算上溢出（单次输入的 `units` 溢出由
  R-12 的慢速夹具覆盖）；两者都变红。
- **非目标**：不做默认参数/重载；v1 不暴露运行时系数（Q-07）。
- **依赖 / 阻塞**：`Str` 已内建（`ct-lang/lib/std/Str.h.ct:18-21`；
  `ct-lang/docs/language-spec.md:2250`；`ct-lang/docs/roadmap.md:52`，v0.36.0）。

### R-10 有状态计数器接口

- **问题**：聊天流、工具输出与文件读取是分片到达的；拼接后再算会分配、会二次拷贝，也违背 O(n)。
- **期望**：提供值类型 `TokenCounter` 与四个操作：
  `token_counter_init(TokenCounter *c)`、
  `int token_counter_feed(TokenCounter *c, const char *p, int len)`、
  `long token_counter_total(const TokenCounter *c)`、
  `long token_counter_finish(TokenCounter *c)`。
  语义：
  - `total()` 只统计**已确认的完整码点**；仍可能构成合法码点的结尾前缀贡献 0，确定非法的字节
    立即计入；随后的 `total()` 不得下降。
  - `finish()` 把残留的未完成前缀按畸形字节逐字节计入，返回最终值；可重复调用，结果不变；
    `finish()` 后 `feed()` 返回 -1 且状态不变。
  - `init()` 重置为可再次使用；`feed()` 参数非法时返回 -1 且状态不变。
  - 结构体大小 ≤ 32 字节，零堆分配，不实现 `Drop`。
- **验收**：
  - `sizeof(TokenCounter) <= 32`；分配拦截器在 `feed/total/finish` 前后计数相等。
  - 4 字节 emoji 在 1/2/3 字节处切开：`total()` 单调不降，`finish()` 后等于整体估算。
  - 两个计数器交错 feed 互不污染；`init()` 后结果与新建一致。
  - `finish()` 连续调用两次返回值相等；`finish()` 后 `feed()` 返回 -1。
- **负例**：把分片先拼进动态缓冲区再调用无状态函数，分配计数非 0；忽略残留前缀的计数器在
  截断夹具上 `finish()` 结果小于整体值；两者都变红。
- **非目标**：不做线程安全容器、不做异步、不做磁盘 spool、不做自动 flush。
- **依赖 / 阻塞**：struct + 固有静态方法已支持（`ct-lang/test/ast/229_inherent_impl/prog.ct:12-15`）。

### R-11 分段累加与整体一致性

- **问题**：「分段算再相加」与「整体算一次」不能有两个答案；四舍五入只能发生一次。
- **期望**：对同一字节序列的任意切分，只要最终调用 `finish()`，计数器结果与
  `token_estimate(p, len)` **逐值相等**；`total()` 在 feed 过程中单调不降。
- **验收**：
  - 每条精确夹具跑 1,000 种随机切分（含 1 字节一片、每个位置切一次、按 UTF-8 序列中间切），
    全部 `finish() == token_estimate(whole)`。
  - 对 `"ab"` 的切分 `"a"+"b"`：无状态分段估算为 1+1=2，整体为 1；计数器必须给 1。
  - `total()` 序列逐项 `>=` 前一项。
- **负例**：把计数器实现成「每片调用无状态函数再相加」，`"ab"` 夹具给出 2，变红；
    不做残留前缀处理的计数器在 emoji 切分上变红。
- **非目标**：不承诺中间 `total()` 等于「该前缀作为最终输入」的估算（它只保证下界与单调）。
- **依赖 / 阻塞**：无。

### R-12 超长输入与数值边界

- **问题**：大文本下不能溢出；累加器要覆盖 `units`，返回类型要留出调用方汇总的余量。
- **期望**：支持 `0 ≤ len ≤ 2^31-1` 字节；`units ≤ 4*len ≤ 2^33`，用 64 位 `long` 累加；
  输出 `tokens ≤ len` 且 `≥ 0`；32 位平台不在支持范围。
- **验收**：
  - 64 MiB 混合内容夹具结果等于逐段累加值，无溢出、无异常。
  - 慢速夹具：以 1 MiB 片喂入 520 MiB 的 `0xFF`，`finish()` 等于 `545,259,520`
    （`520*1024*1024`，每字节 1 token）；用 `int` 累加 `units` 会在此溢出。
  - 随机 1,000 条输入满足 `0 <= est <= len`。
- **负例**：`int` 累加器在 520 MiB 夹具上得到负数或错误值，变红；把中间码点计数收窄成 `int`
  的实现在同一夹具上失败。返回 `long` 的理由是调用方可能把多次估算汇总成一个超过 2^31 的
  预算，不是单次输入会超过 `len`（单次 `tokens <= len`）。
- **非目标**：不支持 >2 GiB 单段输入、不支持 32 位、不做流式落盘。
- **依赖 / 阻塞**：`long` 已支持；`long long` 可用但不要求（`ct-lang/test/ast/31_union/prog.ct:8`）。

### R-13 性能量级

- **问题**：估算会在大上下文上频繁调用，不能变成瓶颈，也不能偷偷分配。
- **期望**：时间 O(n)，每次调用零堆分配，不复制输入；64 MiB 输入在 CI 参考机上 ≤ 1.0 s；
  同一进程内不超过「逐字节求和基线」的 20 倍；4 倍输入耗时不超过 1 倍输入的 5 倍。
- **验收**：
  - `test/run.sh token/perf` 在同一二进制内先跑基线循环（对同样字节做 `sum += p[i]`），再跑估算，
    断言 `t_est <= 20 * t_base` 且 `t_est <= 1.0 s`。
  - `test/run.sh token/perf --scale`：`N=8 MiB` 与 `4N=32 MiB`，`t(4N) <= 5 * t(N)`。
  - 分配拦截器在 64 MiB 调用期间 0 次分配；输入缓冲区地址与内容在调用后不变。
- **负例**：每次调用 `malloc` 一个副本、或用 `strlen` 扫两遍，分配/时间断言变红。
- **非目标**：不做 SIMD、不做多线程、不承诺硬实时；CI 机器差异由 20 倍相对基线吸收。

### R-14 精度误差带

- **问题**：「尽量准」不可判定；必须给出语料、指标、阈值与失败处置。
- **期望**：§2.3 的四类语料全部达标；误差带以离线记录的 `ref` 为分母，不在测试时调用 tokenizer。
- **验收**：
  - `test/run.sh token/corpus all` 读取 `test/fixtures/token/refcounts.tsv`，逐样本计算 `e`、
    聚合比、`p95`、最大欠估，并与 §2.3 的表逐项比较；任一项超界非零退出。
  - 语料清单与 sha256 清单同时存在；缺一条即失败。
  - 扰动测试：把 ASCII 标点权重降为 1 unit，或把 CJK 权重降为 1 unit，至少一条语料带必须失败；
    若仍全绿，说明语料或阈值是空判据，按失败处理。
- **负例**：只断言「est 非空」而不比较 `ref`，扰动测试不会变红，按失败处理；把 `p95` 算成
  平均值会放过长尾，按失败处理。
- **非目标**：不承诺单条输入的误差、不承诺跨模型族一致（Q-01）。
- **依赖 / 阻塞**：**软阻塞**：校准实验与 `refcounts.tsv` 尚未产生（R-15）。

### R-15 校准实验与基线固化

- **问题**：权重表不能凭感觉定；必须有一次可复现的校准，并把结果固化成离线基线。
- **期望**：立项后先做一次校准实验，产出 `docs/calibration.md`（本文件不创建）：
  - 参考 tokenizer 的名称、版本、精确命令与运行环境；
  - 语料来源、许可证、每条样本的 sha256 与 `ref` 计数；
  - 权重搜索过程、最终权重、逐语料残差表与失败样本；
  - 若单档案无法同时满足 §2.3，给出按族拆分方案（Q-01）而不是放宽阈值。
  - 固化文件 `test/fixtures/token/refcounts.tsv`（样本 id、字节数、`ref`、语料类别）与
    `test/fixtures/token/SHA256SUMS`。
- **验收**：
  - `docs/calibration.md` 的命令可在干净环境复跑，`ref` 与固化文件逐值一致。
  - CI 测试只读 `refcounts.tsv`，不联网、不安装 Python/tiktoken、不调用参考 tokenizer。
  - 语料 sha256 不匹配或 `refcounts.tsv` 缺行时，`token/corpus` 非零退出。
- **负例**：把 `refcounts.tsv` 里任一 `ref` 改大 1，聚合比必须变化并可能触发失败；若完全无影响，
  说明测试没读该列，按失败处理。
- **非目标**：不把参考 tokenizer 作为运行时依赖；不在 CI 下载词表；不收录版权不明的语料。
- **依赖 / 阻塞**：**软阻塞**：实验未做；参考族未定（Q-03）。

### R-16 单调性与确定性

- **问题**：预算判断不能因为追加文本而变小；同一输入不能因平台或 locale 变值。
- **期望**：
  - 单调：对任意字节串 `s` 与追加串 `t`，`est(s) <= est(s+t)`；计数器 `total()` 单调不降。
  - 确定：同一版本、同一输入，在 macOS 与 Linux、`LC_ALL=C` 与 `LC_ALL=tr_TR.UTF-8` 下结果相同。
  - 只用整数运算；不使用 `float`/`double`、`isalpha`/`isspace`/`tolower` 等 locale 相关函数。
- **验收**：
  - 对语料每条样本做「逐字节追加、每步估算」，序列单调不降。
  - 同一夹具在两种 `LC_ALL` 下输出逐字节相同；两平台 CI 日志的摘要相同。
  - `grep -nE 'float|double|isalpha|isspace|isdigit|tolower|toupper'` 在实现单元 0 命中。
- **负例**：用 `double` 系数会把 `U+00E9` 的权重在不同编译选项下算出 0.749999，边界夹具变红；
  用 `isspace` 会把某些 locale 下的非 ASCII 空白算进 ASCII 类，跨 locale 断言变红。
- **非目标**：不保证跨权重版本结果相同（权重变更必须 bump 版本并在 CHANGELOG 记录）。
- **依赖 / 阻塞**：无。

### R-17 并发与重入

- **问题**：Agent 内核可能多线程调用；估算不应引入共享可变状态。
- **期望**：实现单元没有可变的文件作用域状态；无状态函数可并发调用；`TokenCounter` 由调用方
  独占，同一实例不并发 `feed`。
- **验收**：
  - `grep -nE '^static '` 在实现单元只允许 `static const` 只读表，其他 `static` 0 命中。
  - 两个线程各调用 `token_estimate` 10,000 次，结果与单线程一致；TSAN 无报告。
  - 两个计数器交错 feed 的结果互不影响。
- **负例**：用共享静态 scratch 缓冲区缓存解码结果，交错/并发夹具出现数据竞争或结果串扰，变红。
- **非目标**：不在计数器内部加锁、不承诺同一实例并发写、不做线程池。
- **依赖 / 阻塞**：线程/原子能力已支持（`ct-lang/test/ast/p41_refcount/prog.ct:20-22`）；
  TSAN 属 CI 环境，**软阻塞**与 R-01 相同。

### R-18 错误处理

- **问题**：错误面必须窄且确定：只有参数错误，内容永不出错。
- **期望**：`token_estimate` 只在 `len < 0` 或 `p == NULL && len > 0` 时返回 `-1`；
  任何字节内容都返回 `>= 0`。`token_counter_feed` 参数非法返回 `-1`，状态不变；
  `finish()` 后再 `feed()` 返回 `-1`。不读写 `errno`，不打印日志，不部分更新状态。
- **验收**：参数矩阵夹具逐项断言返回值；错误调用前后的计数器快照逐字节相等；合法内容（含全
  畸形字节）永不返回 -1。
- **负例**：把 `NULL, len>0` 当空串返回 0，断言变红；错误 feed 先把 `units` 加了一半再返回 -1，
  快照比较变红。
- **非目标**：不定义错误码枚举、不提供错误消息、不做异常。
- **依赖 / 阻塞**：无。

### R-19 文档与门禁可执行

- **问题**：需求与后续文档不能靠「看起来对」；生成块与代码块必须可校验。
- **期望**：`AGENTS.md` 的 1.9.0 生成块由 `sync-agents.sh` 维护，`--check` 退出 0；
  文档中的代码块（立项后）来自 `docs/snippets/` 并被编译/运行；未实现的门禁子命令必须退出 2。
- **验收**：
  - `bash /Users/samxx/trae-ws/.ai-engineering/bin/sync-agents.sh --check AGENTS.md` 退出 0
    （本轮实测）。
  - 立项后 `tools/check.sh` 的未接线子命令退出 2，不得返回 0。
  - README/需求中的示例（立项后）逐字来自 snippet，且 `g4` 能编译运行。
- **负例**：手改生成块内任意字符，`--check` 必须非零；未实现子命令返回 0 视为门禁造假，按失败处理。
- **非目标**：本轮不创建 `tools/check.sh`、不建 snippet、不新增门禁编号。
- **依赖 / 阻塞**：无。

### R-20 发布与安装验证

- **问题**：包要能被安装，版本落点唯一，发布动作受用户授权约束。
- **期望**：`version = 0.1.0`；版本落点只有 `ct.pkg#version`；发布/打 tag 由用户显式指令触发；
  安装后示例能对固定夹具输出预期值。
- **验收**：
  - 干净临时目录 `ct get token@^0.1.0 && ct install`，示例程序输出与精确夹具一致。
  - 打 tag 时 `ct.pkg#version` 等于 tag 去掉 `v` 后的版本。
  - `requires = ct >= 0.36.0` 在本机 `ct` 版本上满足；低于该版本的 `ct` 必须拒绝安装。
- **负例**：把 `requires` 改成高于本机版本后 `ct get` 必须失败；只改 `ct.pkg#version` 不 bump
  tag/CHANGELOG 的一致性检查必须失败。
- **非目标**：本轮不 bump 版本、不打 tag、不 push 发布；不做多包依赖解析。
- **依赖 / 阻塞**：**软阻塞**：本机无 `ct`，安装验证待 CI 或用户环境（R-01 同因）。

## 6 全局非目标（不做什么）

- 不实现 BPE / SentencePiece / WordPiece / Unigram，不训练、不下载、不内置词表或合并表。
- v1 不内置按模型族的预设系数档案；Q-01 若裁定要，另开范围与接口，不在本版偷偷加。
- 不做精确 token 对齐，不承诺与任何 tokenizer 逐 token 一致。
- 不处理多模态输入（图片、音频、视频、PDF、二进制附件）。
- 不做语言学分词、语言识别、简繁转换、词形还原、拼写纠正。
- 不联网、不读文件、不读环境变量、不起线程、不分配堆内存（实现与测试夹具除外）。
- 不建模 chat 模板、role、消息头、工具调用 JSON、special token（Q-04）。
- 不提供裁剪/截断/按预算切分文本（Q-12）。
- 不做字形簇/ZWJ 合并，按 Unicode 码点计数（Q-09）。
- 不提供隐式安全余量；需要时由调用方自行乘（Q-10）。
- 不支持 32 位平台、>2 GiB 单段输入、大端平台的专门适配（Q-11）。
- 不修改 `ct-lang`、不新增语言关键字、不新增门禁编号。
